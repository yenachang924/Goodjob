# 실사용 프로젝트 관제판 설계

상태: 대화에서 방향 승인, 작성 명세 사용자 검토 대기

## 목표와 순서

사용자는 여러 과목·팀 프로젝트·개인 프로젝트에서 무엇이 남았는지, 지금 무엇을 해야 하는지, 실제 시간을 어디에 썼는지 웹 하나에서 파악한다. 백엔드 학습을 실사용의 선행 조건으로 두지 않는다.

1. 첫 구현 단위: 기존 관제판에 프로젝트 상세·마일스톤·하위 작업·시간 기록·오늘/주간 요약을 연결한다. 이 문서가 해당 단위의 명세다.
2. 다음 독립 구현 단위: Google Calendar 읽기 전용 연결로 일정과 가용시간을 통합한다. 아래 연동 경계를 준수하고 OAuth·저장 방식의 상세 명세를 별도로 검토한다. 캘린더 설정이 첫 단위의 사용을 막지 않는다.
3. 공개 배포: 실제 소유자 로그인·저장·재접속 검증 후 진행한다. 코드 구현이나 로컬 실행을 배포 완료로 표현하지 않는다.

Toggl 계정 연결, 캘린더 쓰기, Slack/Obsidian 자동 수집, LLM 시간 예측, 팀 협업은 이 첫 단위에 포함하지 않는다.

## 현재 구현에서 확인한 사실

- `packages/shared/src/planner.ts`: 프로젝트는 문자열 목록, 작업은 단일 깊이이며 마일스톤과 기록 이력이 없다.
- `apps/web/features/cockpit/cockpit.tsx`: 프로젝트별 완료 개수·추천안·수동 확정·실행 중 타이머가 있다. 종료는 active를 비우므로 과거 실제 시간이 남지 않는다.
- `packages/backend/src/handlers.ts`: Supabase 기반 전체 workspace 저장과 revision 충돌 검사가 있다.
- `/learn/tasks`와 `apps/api`는 별도 Kotlin 학습 DB다. 이를 본 관제판으로 전환하거나 이중 쓰기하지 않는다.

## 선택과 대안

기존 Next.js 관제판과 Supabase 저장 경로를 확장한다. 화면·저장·권한 경계를 재사용해 실사용까지 필요한 작업을 줄인다.

Kotlin API를 본 저장소로 교체하는 안은 인증·호스팅·데이터 이전까지 동시에 바뀌므로 이번에는 선택하지 않는다. 브라우저 저장소만으로 대체하는 안도 기기 간 지속성과 데이터 안전 요구에 맞지 않아 선택하지 않는다. 기존 Kotlin 코드는 삭제하지 않는다.

## 사용 화면

- 전체 관제: 프로젝트 카드, 다음 마일스톤, 남은 작업, 지연/막힘, 오늘 기록 시간, 현재 실행 작업.
- 프로젝트 상세: 마일스톤별 작업 트리와 미지정 작업, 프로젝트 메모와 외부 노트 링크, 프로젝트 시간 집계.
- 오늘: 가용시간·추천 초안·사용자가 확정한 계획. 계획에 없는 작업도 타이머를 시작할 수 있다.
- 시간 기록: 오늘/이번 주의 세션 목록과 프로젝트별 합계, 수동 기록 추가와 수정.

작업은 하나의 ID로 저장한다. 프로젝트·전체 목록·오늘 계획에서 같은 작업을 참조하며 복사본을 각각 완료 처리하지 않는다. 확정 계획의 시간 배정은 스냅샷으로 유지하되 현재 작업 상태와 구분한다.

## 프로젝트와 작업 규칙

- 프로젝트에 안정적인 ID, 이름, 선택적 설명/링크를 둔다. 이름 변경으로 연결이 끊어지지 않는다.
- 마일스톤에 프로젝트 ID, 제목, 선택적 목표일, 명시적인 달성 상태를 둔다. 목표일은 일정 예약 시간이 아니라 날짜다.
- 작업에 프로젝트 ID, 선택적 마일스톤 ID, 선택적 부모 작업 ID, 예상 분, 중요도, 마감일, 상태, 생성/완료 시각을 둔다.
- 첫 버전은 부모 작업 + 하위 작업의 2단계만 지원한다. 부모와 다른 프로젝트에 연결하거나 순환 관계를 만들 수 없다. 하위 작업은 부모의 마일스톤을 따른다.
- 상태는 예정·진행 중·막힘·완료다. 타이머 정지는 작업 완료를 뜻하지 않는다. 막힘 이유는 선택적으로 적는다.
- 부모의 상태는 하위 작업에서 집계한다. 부모 체크로 모든 하위를 무심코 완료하지 않는다. 완료한 부모를 분해하려면 먼저 완료를 취소한다.
- 실행 중이거나 확정 계획에 있는 작업을 하위 작업으로 분해하려면 실행을 종료하고 해당 계획을 조정하도록 안내한다. 조용히 기록이나 계획을 지우지 않는다.
- 마일스톤 없이 작업을 즉시 등록할 수 있다. 마일스톤은 할 일을 기록하기 위한 필수 절차가 아니다.
- 첫 버전은 영구 삭제 대신 보관/보관 해제를 제공한다. 실행 중인 작업의 보관은 종료 후 가능하며, 기존 시간 기록은 유지한다.

## 진행률과 규모

- 분모는 보관하지 않은 최하위 실행 작업 수다. 자식이 없는 작업은 자체가 실행 작업이며 부모+자식을 중복 계산하지 않는다.
- 완료율 = 완료 실행 작업 수 / 전체 실행 작업 수. 작업 0개는 100%가 아니라 '등록된 작업 없음'이다.
- 카드에 완료/전체, 남은 개수, 막힘, 지연, 남은 예상 분, 최근 실제 기록 시간을 함께 표시한다.
- 부모 예상 시간은 자식 예상 시간 합계로 표시한다. 작업 시간이 다르므로 개수 완료율을 공수 완료율로 부르지 않는다.
- 주간 추가/완료 수는 생성·현재 완료 시각을 기준으로 표시한다. 완료 취소 시 완료 시각을 비우므로 '완료 클릭 횟수'가 아니라 현재 완료 상태인 작업의 수다.
- 기존 데이터의 생성·완료 날짜를 추측하지 않는다. 날짜가 없는 기존 작업은 누적 진행률에 포함하되 주간 추가/완료 집계에서는 제외한다.
- 작업 추가로 분모가 늘면 완료율이 내려갈 수 있다. 전체 개수와 주간 추가량을 함께 보여 오해를 줄인다.
- 마일스톤은 연결 작업의 완료율과 '달성 확인'을 구분한다. 미완료 작업이 있으면 달성 확인을 막으며, 달성 후 새 작업 추가/재열기는 마일스톤을 다시 진행 중으로 바꾼다. 작업이 없는 마일스톤은 사용자가 명시적으로 달성을 확인할 수 있다.

## 시간 기록

- workspace 전체에서 실행 중인 세션은 하나다. 다른 작업 시작 시 기존 종료와 새 시작을 한 번의 원자적 저장으로 수행한다.
- 세션은 ID, 작업/프로젝트 ID, UTC 시작·종료 시각, timer/manual 출처를 가진다. 실행 중 세션만 종료 시각이 없다.
- 매초 화면 표시만 갱신한다. DB에는 시작·종료·수정 시 저장하며 새로고침 후 저장된 시작 시각에서 경과 시간을 복구한다.
- 날짜가 바뀌거나 탭이 닫혀도 임의 종료·작업 완료를 하지 않는다. 8시간 이상 이어진 세션은 시간을 확인하라는 안내를 제공하며 자동으로 값을 바꾸지 않는다.
- 종료한 시간 기록은 수동 추가·수정할 수 있다. 종료가 시작보다 빠르거나 미래 시각, 다른 기록과 겹치는 구간은 거부한다. 단일 기록 최대 24시간이며 긴 구간은 나누어 입력한다.
- 날짜/주간 집계는 Asia/Seoul 기준, 월요일 시작이다. 자정을 넘긴 기록은 해당 날짜 경계에서 나누어 계산한다. 초 단위 원본을 합산한 뒤 화면에서 분으로 표시한다.
- 완료 시 실행 중 세션도 같은 저장에서 종료한다. 완료 취소로 과거 시간 기록을 삭제하지 않는다.
- 작업을 나중에 분해하더라도 이전 부모의 실제 시간은 프로젝트 집계에 한 번만 남긴다. 자식 작업에 임의로 나눠 배분하지 않는다.
- 진행 중 경과 시간은 확정된 기록 합계와 별도로 표시한다. 타이머 미기록 구간은 휴식/낭비로 분류하지 않는다.
- 1차는 예상 시간과 실제 기록의 비교까지만 제공한다. 자동 예상 보정은 충분한 비교 가능한 기록을 확보한 다음 별도로 구현한다.

## 가용시간과 캘린더 경계

첫 단위는 기존 '오늘 가용 분/완충 분/배치 분' 계산을 유지한다. 이를 시각 기준으로 줄어드는 '오늘 남은 시간'이라고 부르지 않는다.

캘린더 단위에서는 사용자가 가용 시간대를 등록한다. 현재 시각 이후 가용 시간대에서 겹치는 바쁜 일정의 합집합과 완충 시간을 제외하여 남은 가용시간을 계산한다. 실제 기록 시간을 다시 빼서 이중 차감하지 않는다.

- 사용자 선택 캘린더의 일정만 읽고, 생성·수정·삭제는 하지 않는다.
- Google OAuth의 읽기 권한과 서버 측 토큰 보관이 필요하다. Codex용 Google Calendar 플러그인 설치가 웹서비스 OAuth 연결을 대신하지 않는다.
- 종일 일정은 표시만 하고 기본적으로 하루 전체를 차단하지 않는다. 취소 일정과 '한가함' 일정은 시간을 차감하지 않는다.
- 반복 일정은 조회 기간 내 개별 발생 구간으로 다루고, 겹치는 일정은 한 번만 차감한다.
- 연결 해제·만료·네트워크 실패 시 성공 시각과 오류를 표시한다. 캘린더를 못 읽었다고 빈 일정으로 계산하지 않으며 수동 계획은 계속 사용할 수 있다.
- 실제 OAuth 앱 설정과 계정 승인이 없으면 '연동 준비'로 표시한다. 가짜 일정이나 대역 테스트를 실제 연결 완료로 표현하지 않는다.

## 저장·호환성·권한

- 버전 있는 workspace 모델을 도입한다. 기존 프로젝트 이름/작업 ID/완료 상태/계획을 보존하는 순수 변환 함수를 만든다. ID 변환은 재실행해도 동일해야 한다.
- 업그레이드 전 기존 스냅샷을 백업으로 보존하고, 사용자에게 변환 저장을 명시한다. 자동 덮어쓰기나 초기화로 오류를 숨기지 않는다.
- 기존 실행 타이머는 과거 종료 시간이 없으므로 기록을 만들어내지 않는다. 복구 안내에서 사용자가 종료 시각을 확인한 뒤 기록을 저장하거나 기록 없이 취소한다.
- 기존 Supabase 소유자 인증/RLS와 revision 조건부 저장을 유지한다. 다중 탭 충돌은 409와 재조회 안내로 처리하고 실패한 초안을 남긴다.
- 클라우드 설정이 없으면 필요한 연결 항목을 안내한다. 임의 로컬 저장으로 전환하거나 저장 성공을 가장하지 않는다.
- 브라우저 Origin과 Next 내부 주소의 차이는 서버에 설정한 허용 Origin으로 검증한다. 임의 forwarded-host를 신뢰하지 않는다.
- 기존 1MB 저장 한도를 숨기지 않는다. 시간 기록 포함 최대 크기와 목록 제한을 검증하며, 초과 시 내보내기/보관 안내와 함께 저장을 거부한다. 장기 기록 테이블 분리는 별도 단계다.

## 코드 책임과 검증

- shared: 모델 변환, 관계 검증, 진행률, 시간 구간 집계, 추천 대상 필터. UI나 네트워크에 의존하지 않는다.
- backend: 소유자 인증, 입력/Origin 검증, revision 저장. Kotlin 학습 API에는 연결하지 않는다.
- web: 저장 훅, 프로젝트 카드/상세, 작업 트리, 마일스톤, 타이머, 기록 편집을 역할별 파일로 분리한다. 기존 큰 cockpit 컴포넌트의 해당 부분만 분리한다.
- 단위 테스트: 0개/하위 작업/보관/재열기 진행률, 중복 집계 방지, 자정·주간 경계, 시간 겹침, 단일 실행, 변환 반복 안정성.
- 통합 테스트: 인증/소유자 거부, 저장 검증, 변환 데이터 재조회, stale revision 시 세션과 작업 모두 미변경.
- 브라우저 테스트: 프로젝트→마일스톤→하위 작업 등록, 완료율 반영, 타이머 전환·새로고침·종료·수동 수정, 모바일 사용, 저장 실패 시 입력 보존.
- 대역 API 테스트와 실제 Supabase 로그인/영구 저장 검증을 구분한다. 실제 계정 연결이 없으면 실사용 완료 조건은 미충족으로 보고한다.

## 첫 단위 완료 조건

한 화면에서 프로젝트별 남은 규모와 다음 목표를 확인하고, 상세에서 기록한 작업이 전체/오늘에도 같은 상태로 보인다. 실제 시간을 시작·종료·수정하고 주간 프로젝트 합계를 확인할 수 있다. 기존 데이터가 보존되며 실제 로그인 후 재접속해도 변경 내용이 유지된다. 캘린더와 Kotlin 학습 서버는 이 흐름의 필수 의존성이 아니다.

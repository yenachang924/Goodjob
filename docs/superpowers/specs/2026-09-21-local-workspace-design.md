# 로그인 없는 개인 로컬 워크스페이스

## 목적과 승인된 방향

인증 장애와 관계없이 각 사용자가 자기 컴퓨터의 브라우저에서 프로젝트 관리를 시작한다. 사용자와 비교한 세 대안(브라우저 저장, 로컬 서버 DB, 클라우드 인증 수리) 중 브라우저 저장을 선택했다.

## 사용 방식

- 기본 진입 화면에서 로그인 없이 로컬 관제판을 연다.
- 같은 배포 주소를 다른 사람이 열어도 각 브라우저 프로필에 독립적인 데이터가 저장된다. 최초 워크스페이스는 개인 과목이나 샘플 작업이 없는 빈 상태다.
- 프로젝트, 작업과 하위 작업, 마일스톤, 시간 기록, 오늘 계획의 기존 UI와 데이터 모델을 재사용한다.
- 로컬 서버를 실행해서도 사용할 수 있도록 기존 개발 실행 방법을 문서화한다. 로컬 서버 설치는 배포 주소 이용의 필수 조건이 아니다.
- 브라우저 저장은 계정 격리가 아니다. 같은 컴퓨터의 같은 브라우저 프로필을 공유하면 데이터도 공유된다.

## 저장과 데이터 보호

- 로컬 저장 어댑터와 클라우드 저장 어댑터를 분리하고 기존 워크스페이스 훅에 저장 모드를 전달한다.
- 새 전용 브라우저 저장 키를 사용한다. 기존 저장 키와 Supabase 데이터는 자동으로 읽거나 덮어쓰지 않는다.
- 저장 데이터의 형식, 관계, 크기를 기존 검증기로 확인한다. 저장 성공 이후에만 화면에 저장 완료를 표시한다.
- 저장 접근 차단, 용량 초과, 손상된 데이터에는 명확한 오류를 표시한다. 실패 시 빈 데이터로 덮어쓰거나 저장 성공이라고 표시하지 않는다.
- 여러 탭의 수정 충돌을 감지하고 오래된 탭에서의 덮어쓰기를 방지한다. 브라우저 저장소의 동시 쓰기를 직렬화하는 방법을 구현 계획에서 선정한다.
- JSON 내보내기와 빈 워크스페이스에 가져오기를 유지한다. 기존 클라우드 데이터의 자동 이전은 하지 않는다.

## 화면과 클라우드 분리

- '이 브라우저에 저장됨' 표시와 '브라우저 데이터 삭제 시 기록이 지워질 수 있으니 백업하세요' 안내를 제공한다.
- 다른 브라우저, 다른 주소(localhost와 배포 주소 포함), 다른 컴퓨터에서는 별도 저장소라는 점을 안내한다.
- 기존 인증과 비밀번호 복구 기능은 별도 클라우드 진입 경로로 보존한다. 기존 복구 링크도 계속 처리해야 한다.
- 로컬 모드에서는 Supabase 인증이나 /api/workspace 호출을 하지 않는다. 기존 서버 API의 인증·소유자·RLS 보호는 변경하지 않는다.

## 검증 기준

1. Supabase 설정이 없어도 로그인 없이 빈 관제판이 열린다.
2. 프로젝트·작업·시간 기록이 새로고침 후 유지된다.
3. 서로 다른 브라우저 프로필의 데이터가 섞이지 않는다.
4. JSON 백업을 다른 빈 브라우저에 가져올 수 있다.
5. 손상·용량 초과·저장 차단·다중 탭 충돌에서 데이터가 조용히 덮어써지지 않는다.
6. 로컬 흐름에는 인증/워크스페이스 API 요청이 발생하지 않는다.
7. 기존 클라우드 API의 무인증 요청은 거부되며 복구 화면 회귀 테스트를 유지한다.

## 이번 범위 밖

완전 오프라인 설치/PWA, 데스크톱 실행 파일, 컴퓨터 간 자동 동기화, 공동 편집, 클라우드 인증 장애 해결은 포함하지 않는다. 웹 앱을 처음 불러올 때는 인터넷 또는 실행 중인 로컬 서버가 필요하다.

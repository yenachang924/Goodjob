# 프로젝트 관제판 사용하기

이 화면은 루트(`/`)에서 사용합니다. `/learn/tasks`의 Kotlin 학습용 작업 DB와는 별개이며 서로 이중 저장하지 않습니다.

## 하루 사용 흐름

1. 전체에서 프로젝트별 남은 작업과 다음 마일스톤을 확인합니다.
2. 프로젝트 상세에 할 일을 추가합니다. 큰 일은 부모와 하위 작업의 2단계로 나눕니다.
3. 오늘 화면에서 가용 분과 완충 분을 등록하고 추천 초안을 확인한 뒤 확정합니다.
4. 실제 작업을 시작할 때 타이머를 켜고 끝나면 종료합니다. 타이머 종료와 작업 완료는 별개입니다.
5. 시간 기록에서 누락된 구간을 직접 입력하거나 잘못된 기록을 수정합니다.

오늘 화면의 **계획 날짜**로 과거 계획을 열어 조정할 수 있습니다. 확정 계획에 있는 작업을 하위 작업으로 나누려면 해당 날짜의 계획에서 부모 작업을 제외하고 다시 확정하세요. 날짜를 바꾸면 저장하지 않은 초안은 취소됩니다.

저장 중에는 편집과 탭 전환이 잠시 잠깁니다. 작업·마일스톤 수정은 현재 편집을 저장하거나 취소한 뒤 다른 항목을 선택하세요.

## 숫자 읽는 법

- 진행률은 최하위 실행 작업 개수 기준입니다. 부모와 하위를 중복 계산하지 않습니다.
- 할 일을 추가하면 완료율이 내려갈 수 있습니다. 남은 개수와 예상 분을 함께 보세요.
- 기존 작업의 생성·완료 날짜는 추측하지 않으므로 일부 과거 작업은 이번 주 집계에 들어가지 않습니다.
- 기록 시간은 실제로 타이머를 켜거나 직접 입력한 구간입니다. 기록하지 않은 시간을 휴식이나 낭비로 판단하지 않습니다.
- 24시간 넘게 켜 둔 타이머는 자동 종료하지 않습니다. 직접 종료할 때 전체 경과 시간을 보존하면서 최대 24시간짜리 연속 기록으로 나눕니다.
- 가용시간은 직접 등록한 작업 예산입니다. 현재 시각에 따라 줄어드는 잔여 시간이나 캘린더 기반 빈 시간은 아직 아닙니다.

## 저장과 이전

실사용에는 Supabase 설정이 필요합니다. [설정 안내](deployment.md)를 따라 소유자 계정으로 로그인하세요. 테스트용 HTTP 서버는 로컬 검증용 임시 데이터이며 영구 저장소가 아닙니다.

기존 데이터 변환 전 JSON 백업을 보관합니다. 이미 내용이 있는 워크스페이스에 백업을 덮어쓰지 않습니다. 다른 탭의 수정과 충돌하면 먼저 초안을 확인하고 저장본을 다시 불러오세요.

전체 워크스페이스 저장 한도는 1MB입니다. **보관은 삭제가 아니므로 저장 용량이 줄지 않습니다.** 한도에 가까워지면 JSON을 내보내고 장기 기록 저장 구조를 확장해야 합니다.

## 아직 연결하지 않은 기능

Google Calendar는 다음 별도 구현 단위입니다. 읽기 전용 OAuth 동의와 서버 토큰 저장이 필요합니다. Slack/Obsidian 자동 수집, Toggl 계정 연동, LLM 시간 추정은 이번 구현에 포함하지 않습니다.

## 브라우저 검증

`npm run test:e2e:control`은 데스크톱과 모바일을 각각 새 로컬 임시 DB로 실행합니다. 두 프로필이 단일 테스트 계정의 분당 요청 한도를 공유하지 않도록 분리하며 실제 요청 제한 로직은 끄지 않습니다. 다른 개발 서버가 같은 Next.js 개발 빌드 디렉터리를 사용 중이라면 먼저 종료하세요.

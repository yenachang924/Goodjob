# 비밀번호 재설정

계정을 삭제하거나 다시 만들지 않고 기존 사용자 ID와 프로젝트를 유지하며 비밀번호를 변경합니다.

## 사용 순서

1. 로그인 화면에서 **비밀번호를 잊으셨나요?**를 선택합니다.
2. 가입한 이메일을 입력하고 **재설정 메일 보내기**를 누릅니다.
3. 가장 최근 메일의 링크를 한 번만 엽니다. 메일함과 스팸함을 모두 확인합니다.
4. **새 비밀번호 설정** 화면에서 12–128자의 고유한 비밀번호를 두 번 입력합니다. Supabase의 추가 보안 정책도 적용됩니다.
5. 변경 완료 후 로그아웃하고 새 비밀번호로 다시 로그인합니다.

메일 안내는 계정 존재 여부를 공개하지 않습니다. 만료된 링크는 화면에서 메일 재요청을 안내합니다. 성공한 발송 요청 뒤 60초 동안 재요청 버튼을 비활성화하며, 실제 남용 방지는 Supabase Auth의 서버 측 제한을 사용합니다.

## 배포 설정

Supabase Authentication → URL Configuration:

- Site URL: `https://goodjob-web-blue.vercel.app`
- Redirect URLs: `https://goodjob-web-blue.vercel.app/`

앱은 요청한 브라우저의 origin + `/`를 메일 복귀 주소로 사용합니다. 따라서 Production 고정 주소에서 요청하세요. 로컬 테스트 시에는 `http://127.0.0.1:3000/`를 별도로 허용해야 하며, 미리보기 주소를 운영 주소 대신 사용하지 마세요.

Vercel에는 기존 `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`, `COCKPIT_OWNER_ID`, `COCKPIT_WEB_ORIGIN`이 필요합니다. 공개 변수 변경은 새 빌드가 필요합니다. 계정 소유자 UUID는 재설정 때문에 바꿀 필요가 없습니다. 서비스 역할 키는 사용하지 않습니다.

## 보안과 제한

- 비밀번호와 복구 토큰을 앱 로그, 문서, 스크린샷에 기록하지 않습니다.
- SDK가 복구 토큰을 처리하고, 앱은 외부 오류 설명을 그대로 표시하지 않습니다.
- 복구 완료 전 관제판 대신 비밀번호 폼을 보여줍니다. UI 복원을 위한 사용자 ID/단계만 탭 저장소에 저장하며 인증 권한은 Supabase에서 검사합니다.
- 브라우저에서 탭 저장소를 차단한 경우 최초 복구는 가능하지만 새로고침 후 복구 화면 유지가 보장되지 않습니다.
- 이미 만료된 메일은 이 기능을 배포해도 다시 유효해지지 않습니다. 배포 후 새 메일을 요청하세요.
- 테스트는 로컬 Auth HTTP 대역과 실제 SDK를 사용합니다. 실제 메일 전달, Supabase 운영 비밀번호 정책, 운영 계정 로그인은 배포 후 사용자가 별도로 확인해야 합니다.

## 폰트
